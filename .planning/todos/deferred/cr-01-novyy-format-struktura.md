# CR-01: новый формат 1С не получает раздел/подгруппу

## Суть

`parse_new_format` (scripts/upload.py:327) ставит `source_category = ""` —
у нового формата 1С категории нет, группа определяется по текущему каталогу.
Но `apply_structure_mapping` (scripts/upload.py:152) ищет раздел/подгруппу
строго по `source_category`. Для товаров нового формата это пустая строка →
все они попадают в fallback «Прочее»/«Прочее».

## Почему не блокирует этап 5

Expand-contract: этап 5 только ЗАПИСЫВАЕТ новые колонки «Подгруппа»/«Раздел».
Витрина читает их только на этапе 6. До тех пор неверное значение для
новоформатных товаров не видно пользователю. Текущие боевые файлы из C:\price\ —
старого формата (категория есть), для них раскладка корректна.

## Что сделать на этапе 6 (ДО переключения витрины на новые колонки)

Нужен fallback-маппинг для товаров без `source_category`. Варианты:
1. Восстановить категорию новоформатных товаров из колонки «Категория»
   текущего каталога (load_current_groups сейчас тянет только группу — добавить
   и категорию), затем маппить как обычно.
2. Завести вторичную карту `display_group → (раздел, подгруппа по умолчанию)`
   для случаев, когда категории нет. Минус: одна группа («Конфеты и печенье»)
   соответствует двум подгруппам — нужно выбрать подгруппу по умолчанию
   (продуктовое решение владельца).

Также увязать с уточнением формата 1С у 1С-программиста (ожидалось «в понедельник»).
Добавить тест с товаром `source_category == ""`, который сейчас отсутствует.
