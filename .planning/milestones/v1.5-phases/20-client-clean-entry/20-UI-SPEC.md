# Этап 20 — Дизайн-контракт UI: «Чистый вход клиента + история поиска»

> Визуальный и интеракционный контракт для фронтового этапа. Сгенерирован gsd-ui-researcher, проверяется gsd-ui-checker.
>
> **Принцип этапа (от владельца):** «Будь внимателен с ненужными обвесами и нагромождениями, чтобы каталог не превратился в свалку». Каждый элемент оправдывает своё место. При сомнении — не добавлять. Новый визуальный язык НЕ вводим — извлекаем уже существующие токены проекта.
>
> Источник правды по решениям: `20-CONTEXT.md` (D-01…D-11). Этот файл переводит их в точные визуальные/интеракционные параметры на палитре проекта.

## Spacing Scale

Шкала проекта на Tailwind (4px-сетка). Используются эти токены:

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1`, `p-1`, `px-1`, `mt-0.5`≈2px | Зазоры иконок разделов, мелкие подписи |
| sm | 8px | `gap-2`, `px-2`, `py-2`, `p-2` | Внутренний ритм шапки, ряд разделов, элементы списка |
| md | 12px | `px-3`, `py-3`, `gap-3` | Падинги строк-кнопок, заголовки секций |
| lg | 16px | `px-4`, `py-4` | Падинг строки поиска, выпадашки, модалок |
| xl | 24px | `py-6`, `px-6` | Крупные отступы заглушек/пустых состояний |

Exceptions:
- **Высота шапки `h-12` (48px)** — фиксирована (`layout.tsx`), её НЕ менять. Все правки шапки клиента остаются в пределах 48px.
- **Тап-зоны** иконок ряда разделов: `minWidth: 46px` (существующий инлайн-стиль `CatalogNav`), сохранять.
- **Нижний резерв под табами** для модалки/сводки повтора: `padding-bottom: calc(env(safe-area-inset-bottom) + 5rem)` — обязателен (паттерн `ReorderSummaryModal`, этап 19), чтобы контент не уходил под `BottomTabBar` (`h-16` = 64px).
- Историю поиска и строку повтора НЕ перегружать вертикальным воздухом — компактность важнее «дыхания» (B2B, антисвалка).

## Typography

Шкала проекта (Tailwind text-классы). Ровно эти роли:

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 14px | regular (400) | 1.5 | `text-sm` |
| Label / Caption | 12px | regular/medium (400/500) | snug ≈1.4 | `text-xs`, `text-xs font-medium` |
| Heading секции | 16px | semibold (600) | 1.5 | `text-base font-semibold` |
| Заголовок раздела витрины | 18px | bold (700) | 1.4 | `text-lg font-bold` |

Микро-подписи иконок разделов: `text-[9px]` / `text-[10px]` — существующие исключения `CatalogNav`, сохранять.

**Веса:** в проекте по факту 4 ступени (`font-normal` 400, `font-medium` 500, `font-semibold` 600, `font-bold` 700). Для нового UI этапа 20 ограничиться **двумя основными**: regular (400) для тела/подписей и semibold (600) для активных/нажимаемых элементов и заголовков. `font-bold` — только унаследованный заголовок раздела витрины (не вводить новый). `font-medium` допустимо для ссылок-действий (паттерн проекта), но не как основной акцент.

## Color

Палитра извлечена из существующего кода (НЕ выдумана). 60/30/10:

| Role | Value | Tailwind | Usage |
|------|-------|----------|-------|
| Dominant (60%) | белый / очень светлый серый | `bg-white`, `bg-gray-50` | Фон витрины, выпадашка поиска, поверхности строк |
| Secondary (30%) | синий бренда | `bg-blue-600` (шапка), `bg-blue-500`/`bg-blue-400` (состояния) | Шапка, активные чипы разделов/режима, первичные кнопки-действия |
| Accent (10%) | синий-600 + (на синем фоне) белый | `text-blue-600` / `bg-white text-blue-600` | См. список ниже |
| Destructive | красный | `text-red-500`, `text-red-400`, `bg-red-500` (бейдж) | Только: «Очистить»/«Удалить» историю поиска, крестик удаления запроса |

**Accent reserved for (точный список, не «все интерактивные»):**
1. Первичная кнопка-строка **«↻ Повторить последний заказ»** — `bg-blue-600 text-white`, `active:bg-blue-700` (тот же стиль, что кнопка «Повторить заказ» в `orders/page.tsx`).
2. Кнопка **«Перейти в корзину →»** в сводке повтора — `bg-blue-600 text-white` (унаследовано из `ReorderSummaryModal`).
3. **Активный** раздел/режим в шапке — инверсия `bg-white text-blue-600` (паттерн `CatalogNav`).
4. Ссылки-действия в сводке/выпадашке («← Корзина», подобные) — `text-blue-600`.

**Не-accent (намеренно нейтральные):**
- Строки истории поиска — текст `text-gray-700/800` на `bg-white`, иконка «часы» `text-gray-400`. История поиска **не должна** соперничать по яркости с кнопкой повтора и витриной (антисвалка). Hover/active — лёгкий `bg-gray-50`/`active:bg-gray-100`.
- Иконки исходов сводки повтора сохраняют семантику этапа 19: `text-green-500` (успех), `text-blue-500` (цена изменилась), `text-gray-400` (нет в наличии), `text-red-400` (недоступен), `text-amber-500` (усечено остатком). Эту палитру НЕ менять.

**Бейджи-счётчики** (если применимо рядом с разделами) — `bg-red-500 text-white` круглый (паттерн `CartIcon`/`BottomTabBar`); в этом этапе новых счётчиков не вводим.

## Copywriting Contract

Тексты на русском, тон — деловой и честный (B2B). Инвариант D-11: нигде не «статус/принято/подтверждено» — только «отправленные заказы»/«что я отправил».

### Строка быстрого повтора (D-06)

| Element | Copy |
|---------|------|
| Primary CTA (строка над каталогом) | **↻ Повторить последний заказ** |
| Условие показа | только роль `client`, после `ready`, и только если `entries.length > 0` (`useOrderHistory`). Иначе строки нет вовсе. |
| Результат — успех | **Добавлено {N} {товар/товара/товаров} в корзину** (склонение `pluralGoods`, переиспользовать из `orders/page.tsx`) |
| Результат — частично | строки исходов как в этапе 19: «нет в наличии» / «товар больше недоступен» / «добавлен · цена изменилась: {old} → {new}» / «добавлено {addedQty} из {requestedQty} — ограничено остатком» |
| Результат — нечего добавить | **Ни одного товара из заказа сейчас нельзя добавить** (корзину НЕ открывать, кнопки перехода нет — D-06/D-07) |
| Переход после успеха | **Перейти в корзину →** (`bg-blue-600`, только при `addedCount > 0`) |

Реализация сводки — переиспользовать `ReorderSummaryModal` (bottom-sheet с safe-area + 5rem), не изобретать новый. Триггер — `classifyReorder(lastEntry.items, products, priceForm)` + `addToCartWithQuantity` для исходов `added`/`price_changed`.

### История поиска (D-07, D-08)

| Element | Copy |
|---------|------|
| Появление | при фокусе на поле поиска, под `SearchBar`, если есть сохранённые запросы и поле пустое/в фокусе |
| Заголовок списка (опционально) | **Недавние запросы** (`text-xs text-gray-400`, без давления; можно опустить если тесно) |
| Пункт списка | сам текст запроса (`text-sm text-gray-800`), слева иконка-часы `text-gray-400`, справа крестик удаления `✕` `text-gray-400` |
| Удалить один запрос | крестик `✕` у пункта — без подтверждения (действие лёгкое, обратимое повторным поиском) |
| Очистить весь список | **Очистить** (`text-xs text-red-500 font-medium`, справа в заголовке — паттерн `orders/page.tsx`) |
| Пустое состояние | списка просто НЕТ (не показываем «история пуста» — лишний шум) |
| Подсказка-плейсхолдер поля | **Поиск товара...** (существующий, не менять) |

Запись запроса — при выполнении поиска (`setSearch` с непустым значением; разумно — по debounce/выходу из поля, на усмотрение исполнителя), дедуп (свежие сверху), потолок ~8–10, мягкая деградация битых данных (паттерн `useOrderHistory`/`useSearchHistory`). Ключ localStorage — в духе `catalog-*` (например `catalog-search-history`).

### Шапка клиента (D-03, D-04)

| Element | Copy / поведение |
|---------|------|
| Верх справа (client) | только **⚙ Настройки** (`SettingsButton`). ♥ Избранное и 🛒 Корзина — убрать (дублируют нижние табы) |
| Верх справа (sales) | **БЕЗ ИЗМЕНЕНИЙ**: ↻ SyncButton + ⚙ + 🛒 |
| Освободившееся место | отдать ряду разделов `CatalogNav` (разделы на первый план) |
| Переключатель режима | «Каталог / ★ Хит / ✦ Новинка» — компоновать так, чтобы не теснил разделы (точная вёрстка — исполнителю) |

### Destructive confirmation

| Action | Подтверждение |
|--------|---------------|
| Удалить один запрос истории поиска | без `confirm()` — лёгкое обратимое действие, крестик `✕` |
| Очистить всю историю поиска | без модалки достаточно; допускается `confirm('Очистить историю поиска?')` по образцу `orders/page.tsx` — на усмотрение исполнителя (список тривиально восстановим поиском) |

В этом этапе **нет тяжёлых деструктивных операций** (не трогаем заказы, корзину, серверные данные).

## Interaction & Layout Contract (специфика этапа)

| Контракт | Требование |
|----------|-----------|
| SSR-safe гейт роли (D-05/D-10) | Любые завязки на роль рендерятся **только после `ready`** из `useRole`. До `ready` — нейтральный дефолт (резерв места, как `HeaderPrimaryAction` отдаёт `<div className="h-9 w-9" />`). Никакого мелькания/сдвига раскладки. |
| Гейт строки повтора | `if (!ready \|\| role !== 'client') return null;` (паттерн `BottomTabBar`) + доп. условие `entries.length > 0`. |
| Место строки повтора | над списком каталога в `CatalogView` (между `SearchBar` и контентом), компактная **одна строка**, не блок-витрина (D-06). Высота в пределах ~40–48px, `bg-white`, нижняя граница `border-b border-gray-100` для отделения от витрины. |
| z-index / sticky | Шапка `sticky top-0 z-50 bg-blue-600` — не трогать. Сводка повтора — оверлей `z-50` `bg-black/40` + bottom-sheet (как `ReorderSummaryModal`). Выпадашка истории поиска — позиционируется под `SearchBar`, `z` ниже шапки, поверх витрины (`absolute`/`relative` контейнер). |
| Офлайн-безопасность (D-09) | История поиска и строка повтора читают только localStorage / `useCatalogSyncContext` (IndexedDB). **Никаких** новых сетевых вызовов на старте. `force-dynamic` + `cache:"no-store"` витрины НЕ трогать. |
| Safe-area / PWA | Не ломать standalone + safe-area. Любой нижний контент (модалка) учитывает `env(safe-area-inset-bottom)` + резерв под `BottomTabBar` (5rem). |
| Нативность | Поведение «как у Ozon/WB»: история запросов выпадает при фокусе, тап повторяет запрос, крестик удаляет; повтор — в один тап. Без новых визуальных паттернов. |
| Доступность | Кнопки — `aria-label` где иконочные (паттерн `BottomTabBar`/`FavoritesIcon`); тап-зоны ≥ 44px для иконочных действий. |
