# Phase 6: Двухуровневая навигация на витрине - Context

**Gathered:** 2026-06-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Этап перестраивает **навигацию витрины** (Next.js) с плоских 14 групп на двухуровневую: 5 разделов → подгруппы → товары. Слой данных уже готов (Этап 5) — в Google Sheet у каждого товара заполнены колонки «Подгруппа» (J) и «Раздел» (K), товары уже отсортированы `upload.py` по порядку из `structure_map.json`.

**Доставляет:**
1. Витрина читает новые колонки «Подгруппа»/«Раздел» из Sheet (расширение диапазона чтения).
2. Главная страница каталога = единая прокручиваемая витрина: все товары видны сразу, сгруппированы заголовками **раздел → подгруппа**, в порядке из карты структуры (паттерн «меню-якорь» как в приложениях доставки еды).
3. Прилипающая сверху полоса из разделов; тап = плавная перемотка к разделу; активный раздел подсвечивается при прокрутке (scroll-spy).
4. Поиск и вкладки «Хит»/«Новинка» работают поверх новой структуры — не ломаются.

**Вне этого этапа:**
- Слой данных (`structure_map.json`, `upload.py`) — сделан на Этапе 5, НЕ трогаем.
- Админ-панель с выбором подгруппы — Этап 7.
- Удаление/чистка старой колонки «Группа» — отложено на Этап 7 (приём expand-contract: сначала витрина переходит на новые поля, потом решается судьба «Группы»).
- Карточки товаров, корзина, режимы отображения (сетка/список/презентация), просмотрщик фото — переиспользуются как есть, не переделываются.
</domain>

<decisions>
## Implementation Decisions

### Модель навигации (NAV-01, NAV-02, NAV-03)
- **D-01:** Главная = одна длинная прокручиваемая витрина по паттерну **«меню-якорь» (anchor navigation)** — как в приложениях доставки еды (Яндекс.Еда, Delivery Club). Все товары видны сразу, сгруппированы заголовками раздел → подгруппа, листаются сверху вниз. НЕ классический свёрнутый аккордеон с тапами-на-раскрытие. Решение владельца: «вижу весь магазин, разложенный по полкам, листаю».
- **D-02:** Сверху — **прилипающая (sticky) полоса разделов** (заменяет текущую `CategoryFilter` с плоскими кнопками-группами). Тап по разделу = плавная перемотка (scroll-to-anchor) к этому разделу на странице, БЕЗ перехода на отдельный экран и без перезагрузки. Активный раздел в полосе автоматически подсвечивается по мере прокрутки (scroll-spy).
- **D-03:** Товары внутри подгруппы показываются теми же карточками/режимами, что и сейчас (сетка 2/3/4 колонки, список, презентация, фото — `ProductCard`, `CatalogSettings`). Никаких новых компонентов карточек.

### Порядок (NAV-04)
- **D-04:** Порядок разделов и подгрупп берётся **из данных** — `upload.py` уже сортирует строки Sheet по (порядок раздела, порядок подгруппы, порядок категории) из `structure_map.json`. Витрина выводит разделы/подгруппы в порядке **первого появления** в полученном (уже отсортированном) списке товаров. Никакой отдельной загрузки `structure_map.json` в Next.js не требуется — порядок «приезжает» вместе с данными. Захардкоженный `GROUP_ORDER` в `CatalogView.tsx` удаляется/заменяется.

### Новинки (продолжение логики Этапа 1)
- **D-05:** «Новинки» — **отдельный первый раздел** на витрине и первая позиция в полосе разделов (продолжает решение «Новинки первыми» из Этапа 1). Туда же попадают товары, у которых поле «Раздел» пустое (непокрытые/новые товары) — ничего не теряется, ни один товар не выпадает из навигации. Логика по образцу текущей изоляции новинок.

### Поиск и вкладки Хит/Новинка (NAV-05)
- **D-06:** При активном поиске (непустая строка) ИЛИ во вкладках «Хит»/«Новинка» (`?filter=hit|new`) показывается **плоский список** найденного по всему каталогу — разделы, подгруппы и прилипающая полоса на это время скрываются. Это сохраняет текущее поведение (`SearchBar` + фильтр по badge в `page.tsx`), ничего не ломая. Группировка возвращается, как только поиск очищен и фильтр снят.

### Чтение данных
- **D-07:** `lib/sheets.ts` расширяет диапазон чтения с `A2:I` до `A2:K`; `Product` (в `lib/types.ts`) получает поля `subgroup` (J = «Подгруппа») и `section` (K = «Раздел»). Подтверждённый порядок колонок Sheet: A Наименование · B Цена · C Остаток · D Категория · E Группа · F Поставщик · G Badge · H ImageUrl · I Description · **J Подгруппа · K Раздел**.

### Claude's Discretion (решено по аналогии — владелец дал свободу, правки потом на готовом проекте)
- **Счётчики:** рядом с заголовком подгруппы — ненавязчивый счётчик товаров (помогает B2B-покупателю оценить ассортимент). Уровень раздела — на усмотрение исполнителя.
- **Пустые подгруппы/разделы:** не отрисовываются, если в них нет товаров с остатком > 1 (фильтр `stock > 1` уже есть). Пустых заголовков на витрине быть не должно.
- **Кнопка «Все»:** отдельная не нужна — по умолчанию и так видно всё; первая кнопка в полосе = «Новинки». Возврат наверх обеспечивает существующий `ScrollToTop`.
- **Внешний вид заголовков:** раздел — крупный жирный заголовок-разделитель; подгруппа — заголовок поменьше. Стиль — в духе текущего синего UI (Tailwind), консистентно с шапкой и `CategoryFilter`.
- **Полоса разделов:** прилипает под синей шапкой; подгруппы в полосу НЕ выносятся (только 5–6 разделов), подгруппы — это in-page заголовки.
- Точная техника scroll-spy и плавной перемотки (IntersectionObserver / scrollIntoView) — на усмотрение исполнителя.
</decisions>

## Existing Code Insights

### Reusable Assets
- `ProductCard`, `CatalogSettings`/`useCatalogSettings`, `Lightbox`, `ScrollToTop`, `SearchBar`, `NavTabs` — переиспользуются без изменений; этап меняет только слой группировки/навигации над ними.
- Логика «Новинки первыми» (`GROUP_ORDER[0]` в текущем `CatalogView`) — переносится в новый раздел-первым (D-05).
- Фильтр `stock > 1` и фильтр поиска по `name` в `CatalogView` — сохраняются.

### Established Patterns
- **Данные → витрина:** `lib/sheets.ts` читает лист «Товары», `page.tsx` (`force-dynamic`/`revalidate: 300`) отдаёт в `CatalogView`. Новые поля идут тем же путём — только расширить диапазон и тип.
- **Клиентская фильтрация в `CatalogView`** (`useMemo` по группе/поиску) — группировка раздел→подгруппа делается тем же приёмом, на клиенте, из уже полученного массива.
- **TypeScript + функциональные компоненты + только Tailwind** (стандарты проекта) — новый компонент полосы разделов и группировки следуют им.

### Integration Points
- `CatalogView` — центральная точка: сюда добавляется группировка по `section`/`subgroup`, scroll-spy, ветка «плоский список при поиске/фильтре» (D-06).
- Новая/переделанная `CategoryFilter` → прилипающая полоса разделов с якорной перемоткой.
- `getProducts()` в `lib/sheets.ts` — единственное место чтения данных; правка диапазона A2:K локализована здесь.

## Specific Ideas

- Эталон UX — **меню приложений доставки еды**: прилипающая полоса категорий + длинная прокрутка + автоподсветка активной категории + перемотка по тапу. Владелец описал именно это: «весь магазин разложен по полкам, листаю».
- Порядок разделов на витрине: **Новинки → Сладкое → Напитки → Крупы/лапша/бакалея → Соусы и консервация → Снэки и прикассовое** (Новинки добавлены первыми поверх 5 разделов из `structure_map.json`).
- Внутри разделов порядок подгрупп из карты: Энергетики последними в «Напитках», «Коробочные конфеты» (Подарочные) кластером в конце «Конфет» — это уже обеспечено сортировкой `upload.py` (Этап 5), витрина просто сохраняет порядок данных.
</specifics>
