# Этап 14: Install Prompt (Android + iOS) — Контекст

**Собрано:** 2026-06-13
**Статус:** Готов к планированию
**Источник:** Сжатое обсуждение (2 продуктовых вопроса) + анализ кодовой базы сеньором

<domain>
## Граница этапа

Этап добавляет агенту (владельцу магазина) **подсказку об установке каталога как приложения на домашний экран** и постоянный путь к установке через настройки. Фундамент PWA уже стоит (этап 10): `app/manifest.ts` с `display: standalone`, Service Worker `app/sw.ts`, иконки в `/public/icons/`. Этот этап — только клиентский UX поверх готового фундамента.

**Закрывает требование:** PWA-02 — «На Android агент получает подсказку об установке; на iPhone — понятная инструкция „Поделиться → На экран Домой“».

**Что НЕ входит:** генерация иконок/манифеста (сделано в этапе 10), офлайн-данные (этапы 11–13), push-уведомления.
</domain>

<decisions>
## Решения по реализации

### D-01: Поведение подсказки — после знакомства, один раз (ПРОДУКТОВОЕ РЕШЕНИЕ владельца)
- Подсказка появляется **не сразу**, а после «сигнала вовлечённости»: агент немного полистал каталог (скролл/взаимодействие) ИЛИ прошло ~20–30 секунд на странице — что наступит раньше.
- Показывается **однократно**. Если агент закрыл (крестик/«Позже») — больше при следующих визитах баннер/шторка не появляется.
- Цель — не раздражать (критерий успеха #3 «повторные визиты не надоедают»).

### D-02: Android — перехват штатного события браузера
- Слушаем событие `beforeinstallprompt`, вызываем `preventDefault()` и сохраняем событие в ref/state (отложенный показ — браузер по умолчанию решает сам, мы берём контроль).
- По сигналу вовлечённости (D-01) показываем **свой аккуратный баннер снизу** с кнопкой «Установить».
- По клику на «Установить» вызываем `savedEvent.prompt()` и обрабатываем `userChoice` (accepted/dismissed).
- Браузер запускает событие только если выполнены критерии устанавливаемости (manifest + SW + HTTPS) — все они уже есть.

### D-03: iPhone (iOS Safari) — собственная шторка-инструкция
- На iOS события `beforeinstallprompt` НЕ существует (Apple его не поддерживает) — поэтому показываем свою **bottom-sheet шторку снизу** с пошаговой инструкцией: «Нажмите „Поделиться“ ⬆️ → „На экран „Домой““».
- Детект iOS Safari: `navigator.userAgent` (iPhone/iPad/iPod) И НЕ standalone (`navigator.standalone !== true` и `display-mode: standalone` не активен). Учесть, что на iPadOS UA может маскироваться под Mac — допускается простая эвристика для iPhone (основная цель — телефон агента).
- Инструкция должна быть понятна без технических знаний: текст + иконка системной кнопки «Поделиться».

### D-04: Однократность и «уже установлено» — localStorage + проверка standalone
- Флаг показа храним в `localStorage` (например, ключ `pwa-install-dismissed`). При наличии флага — не показываем баннер/шторку автоматически.
- Если приложение УЖЕ запущено как установленное (`window.matchMedia('(display-mode: standalone)').matches` ИЛИ `navigator.standalone === true`) — подсказку не показываем вообще и пункт в настройках скрываем/делаем неактивным.
- localStorage оборачивать в try/catch — приватный режим iOS может бросать (грабли, уже встречались на этапе 13, T-12-02).

### D-05: Постоянная кнопка «Установить приложение» в настройках (ПРОДУКТОВОЕ РЕШЕНИЕ владельца)
- В панели настроек (`components/SettingsPanel.tsx`, открывается по шестерёнке) добавить пункт **«Установить приложение»**.
- На Android — вызывает сохранённое событие `beforeinstallprompt` (если оно доступно); если событие ещё не пришло — показывает короткую подсказку.
- На iOS — открывает ту же шторку-инструкцию (D-03).
- Пункт **скрывается**, если приложение уже в standalone-режиме (D-04) — устанавливать нечего.
- Это страховка: баннер показан один раз, но возможность установить всегда под рукой.

### D-06: Архитектура — новый клиентский «остров» по образцу OfflineBar
- Создать клиентский компонент `components/InstallPrompt.tsx` (`"use client"`), смонтировать в `app/catalog/[secret]/layout.tsx` рядом с `<OfflineBar />`.
- Образец для подражания: `components/OfflineBar.tsx` (структура, useEffect-подписки, try/catch вокруг хранилища, sticky/fixed-позиционирование, фирменные цвета).
- Состояние установки (сохранённое событие + standalone + dismissed) логично вынести в небольшой хук или общий провайдер, если кнопка настроек и баннер должны делить одно событие. Решение об общем хуке/контексте — на усмотрение планировщика (аналог `CatalogSyncProvider`).

### D-07: Корректность standalone-режима (критерий успеха #4)
- После установки каталог должен занимать весь экран без лишних отступов и без адресной строки.
- Учесть «safe-area» (вырез/чёлка iPhone): использовать `env(safe-area-inset-*)` для нижней шторки и баннера, чтобы они не перекрывались системными зонами. Проверить, что `viewport-fit=cover` присутствует (или добавить), иначе safe-area не работает.

### D-08: Брендинг и стиль
- Фирменный синий `#2563eb` (как шапка `bg-blue-600`), белый фон шторки/баннера, скруглённые углы, мягкая тень — единый язык с существующими островками (OfflineBar, SettingsPanel).
- Баннер/шторка — `fixed` снизу (`bottom-0`), поверх контента, с возможностью закрыть (крестик или «Позже»).

### Claude's Discretion (на усмотрение планировщика/исполнителя)
- Точная механика «сигнала вовлечённости» (порог скролла vs таймер) — выбрать простую и надёжную.
- Делить ли событие через хук/контекст или продублировать логику детекта — выбрать по чистоте кода.
- Точные тексты микрокопии (кроме сути инструкции iOS) — подобрать дружелюбные и короткие.
- Анимация появления шторки (slide-up) — желательна, но не обязательна.
</decisions>

<specifics>
## Конкретные требования

- Критерии успеха этапа (из ROADMAP.md, Этап 14) — все 5 должны стать ПРАВДОЙ:
  1. Android: баннер «Установить» после просмотра; после установки — запуск с домашнего экрана без браузерной строки.
  2. iPhone/Safari: bottom-sheet с инструкцией «Поделиться → На экран Домой», понятной без техзнаний.
  3. Промпт однократный — повторные визиты не надоедают.
  4. Standalone отображается корректно: нет лишних отступов, нет адресной строки, весь экран.
  5. Проверка на реальном iPhone (ручная приёмка — может быть отложена, как на этапе 13).
- Деплой: только `git push` → Vercel автодеплой. Серверная часть (daniella) не затрагивается.
</specifics>
