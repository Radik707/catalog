## Свежесть против скорости (стратегия синхронизации)

| Option | Description | Selected |
|--------|-------------|----------|
| Мгновенно из памяти + тихое обновление | Показать данные из IndexedDB сразу, в фоне дотянуть свежее и бесшовно подменить. Мгновенный старт, цены практически всегда свежие (прайсы раз в день) | ✓ |
| Онлайн — ждать свежее | При наличии сети дождаться ответа сервера и только потом рисовать; память — только офлайн-резерв. Свежее, но старт медленнее на слабой сети | |

**User's choice:** Мгновенно из памяти + тихое обновление (рекомендация сеньора)
**Notes:** Ключевой фактор — прайсы обновляются раз в день, поэтому фоновая подмена почти незаметна, а выигрыш в скорости для агента в полях большой. Подмену делаем бесшовной (прокрутка и фильтры не сбрасываются).

## Первая загрузка (пустая память, идёт fetch)

| Option | Description | Selected |
|--------|-------------|----------|
| Скелетон-карточки | Серые контуры карточек в сетке с мерцанием; в стиле витрины, не выглядит сломанным на слабой сети | ✓ |
| Спиннер с подписью | Крутящийся кружок + «Загружаем каталог…»; просто и быстро сделать | |
| Ничего (пустой экран) | Не показывать ничего до прихода данных; на медленной сети похоже на зависание | |

**User's choice:** Скелетон-карточки (рекомендация сеньора)
**Notes:** Агент часто на слабой мобильной сети — скелетон даёт честный сигнал «работаем».

**Notes:** Снимает тревогу и даёт конкретное действие; ручная кнопка не нужна — приложение само заметит появление сети.

## Claude's Discretion

Владелец согласился, что эти моменты — чисто инженерные, решаются без него (озвучены и приняты явно перед записью):
- Обработка ошибки сервера при наличии сети → вести себя как офлайн (показать кэш или то же сообщение), технические ошибки не показывать.
- Скрытые товары офлайн → у офлайн-агента старое состояние до следующей синхронизации (природа офлайна; принято как норма).
- Индикатор свежести «данные за ЧЧ:ММ» сознательно НЕ делаем на этом этапе → это этап 12; сейчас только пишем `syncTimestamp` в память.
- Версионирование схемы IndexedDB (аккуратное пересоздание при будущем изменении формата Product) — закладывается в реализацию.
- Формат базы (`catalog-db`, stores `products`/`meta`), обёртка `idb`, внутренняя логика `useCatalogSync`, вызов `navigator.storage.persist()`, точные тексты и визуал.
