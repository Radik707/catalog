# Phase 12: Офлайн-UX (индикаторы и корзина) - Context

**Gathered:** 2026-06-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Этап делает офлайн-режим **видимым и понятным агенту**. После этапа 11 каталог уже открывается без сети, но агент не видит, в каком он режиме и насколько свежие данные. Этот этап добавляет три вещи:

1. **Индикатор сети и свежести** — полоска статуса в шапке: онлайн/офлайн + время последней синхронизации (SYNC-03).
2. **Подтверждение офлайн-корзины** — набор/удаление товаров работает без сети (CART-01). Технически уже работает (корзина в localStorage) — этап в основном *проверяет и закрепляет* это.
3. **Защита отправки заказа** — офлайн кнопка «Отправить заказ» заблокирована с понятным пояснением, заказ при этом не теряется молча (CART-02).

**Требования этапа:** SYNC-03 (видно состояние сети + метка «данные за ЧЧ:ММ»), CART-01 (корзина набирается офлайн), CART-02 (отправка требует сети, офлайн-блокировка без потери заказа).

**Вне этого этапа** (см. Deferred Ideas): кнопка «Обновить каталог» и умный кэш/diff фото — этап 13; install prompt (Android-баннер / iOS-инструкция) — этап 14; прогресс синхронизации (SYNC-04) — v1.3.x.

</domain>

<decisions>
## Implementation Decisions

> Владелец дал явный мандат на этом этапе: «Если знаешь решение, что будет лучше и правильнее — делай сам, ко мне только за очень важными правками». Все решения ниже приняты Claude в роли сеньора; продуктовых развилок, требующих участия владельца, на этом этапе нет.

### Индикатор сети и свежести данных (SYNC-03)
- **D-01 (когда показывать):** Полоска статуса видна НЕ всегда. Три состояния:
  - *Онлайн + данные свежие (< 24 ч)* → полоска **скрыта** (чистая шапка, агента не отвлекаем). Удовлетворяет критерию успеха №1 («при подключении полоска исчезает»).
  - *Офлайн* → спокойная **нейтральная** (серая) полоска «Офлайн • данные за 08:30».
  - *Данные старше 24 ч* (онлайн ИЛИ офлайн) → **жёлтая** полоска-предупреждение. Удовлетворяет критерию успеха №2.
- **D-02 (где):** Тонкая полоса (~24px, мелкий текст) **сразу под синей шапкой**, на всю ширину, sticky под шапкой. НЕ внутри синей шапки — там тесно (навигация + настройки + корзина) и отдельная клиентская строка технически чище (синяя шапка — серверный компонент).
- **D-03 (тон офлайн):** Офлайн оформляем спокойно-нейтрально (серый/приглушённый), **НЕ красным/тревожным**. Для торгового агента в полях офлайн — рабочая норма, а не ошибка. Тревожный цвет приберегаем только для жёлтого «данные устарели».

### Формат метки свежести (SYNC-03)
- **D-04:** Абсолютное время с адаптацией по дате:
  - сегодня → «данные за 08:30»
  - вчера → «данные за вчера, 08:30»
  - раньше → «данные за 10 июня, 08:30» (дата + время)

  Абсолютное, а не относительное («2 часа назад») — точнее отвечает на вопрос «насколько свеж каталог». Агент обновляется утром разово, поэтому «за 08:30» читается естественно. Порог 24 ч переключает цвет на жёлтый (D-01).

### Кнопка «Отправить заказ» офлайн (CART-02)
- **D-05:** Офлайн кнопка **выключена** (серая, `disabled`) + **постоянная подпись** под ней: «Нет сети — заказ отправится, когда появится интернет. Корзина сохранена.» Выключенная кнопка сразу честно показывает «сейчас нельзя» — лучше, чем кнопка, которая ругается только при нажатии (та провоцирует мысль «сломалось»). При появлении сети кнопка включается сама. Корзина сохраняется (она в localStorage — не теряется в любом случае). **Касается ОБЕИХ кнопок отправки**: плавающей `components/TelegramButton.tsx` (в layout) и локальной в `app/catalog/[secret]/cart/page.tsx`.

### Корзина офлайн (CART-01)
- **D-06:** Никаких офлайн-специфичных отличий в самой корзине. Добавление/удаление/изменение количества работают одинаково онлайн и офлайн (уже так — `localStorage` через `useCart.ts`). Никаких бейджей/пометок «офлайн» на корзине. Единственное офлайн-отличие во всём корзинном потоке — заблокированная кнопка отправки (D-05). Ментальная модель агента: «набирай спокойно, отправишь при сети». CART-01 на этом этапе — преимущественно **проверка**, что это действительно работает офлайн (включая ручную iPhone-проверку, критерий успеха №5).

### Claude's Discretion
Чисто инженерные решения — планировщик/исполнитель определяют детали; продуктового видения владельца тут нет:
- **Общий источник статуса сети:** вынести лёгкий хук `useOnlineStatus()` (`navigator.onLine` + слушатели событий `online`/`offline`), переиспользуемый и полоской-индикатором, и кнопкой отправки. НЕ запускать тяжёлый `useCatalogSync` второй раз ради статуса — он уже работает внутри `CatalogView`. Полоска читает `syncedAt`: либо из общего состояния, либо напрямую из IDB через `getMeta("syncTimestamp")` (`lib/catalogDb.ts`).
- **Полоска в серверном layout:** реализуется как отдельный клиентский компонент-«остров», вставленный в `app/catalog/[secret]/layout.tsx` под `<header>`.
- Точные пиксели/оттенки полоски и финальные тексты — в рамках существующего стиля (Tailwind, синяя шапка `blue-600`).
- Утилита форматирования времени (D-04) — новая, маленькая, без внешних библиотек дат.

## Existing Code Insights

### Reusable Assets
- `lib/useCatalogSync.ts` — уже экспортирует `isOnline` (по событиям `online`/`offline`) и `syncedAt` (unix-ms последней синхронизации). Половина данных для индикатора готова — строить заново не нужно.
- `lib/useCart.ts` — корзина в `localStorage` (`catalog-cart`). Добавление/удаление **уже работают офлайн** — CART-01 в основном проверка, не разработка.
- `lib/catalogDb.ts` — `getMeta("syncTimestamp")`: альтернативный источник времени синхронизации без запуска полного хука.

### Established Patterns
- `app/catalog/[secret]/layout.tsx` — синяя шапка (`bg-blue-600`, sticky, `max-w-screen-2xl`). **Серверный компонент** (`async`, `await getProducts()`). Полоска-индикатор (D-02) встраивается под `<header>` как отдельный **клиентский** компонент-остров.
- `app/catalog/[secret]/cart/page.tsx` — локальная функция `TelegramButton` (строка ~139): собирает текст заказа и открывает `https://t.me/...`. Сюда же — офлайн-блокировка (D-05).
- `components/TelegramButton.tsx` — плавающая кнопка отправки, импортируется в layout. **Вторая точка** офлайн-блокировки (D-05) — обе кнопки должны вести себя одинаково.

### Integration Points
- Новые файлы (ориентировочно): `lib/useOnlineStatus.ts` (общий статус сети), маленький компонент полоски-индикатора, утилита форматирования «данные за …» (D-04).
- Точки стыковки: `layout.tsx` (вставка полоски под шапку), обе кнопки отправки (`cart/page.tsx` + `components/TelegramButton.tsx`) читают `useOnlineStatus()` для блокировки.

## Specific Ideas

- **Тексты-ориентиры** (финальные формулировки — на усмотрение исполнителя в рамках стиля):
  - Офлайн-полоска: «Офлайн • данные за 08:30»
  - Жёлтая полоска (данные старше суток): тот же формат свежести + визуальное предупреждение
  - Подпись под выключенной кнопкой заказа: «Нет сети — заказ отправится, когда появится интернет. Корзина сохранена.»
- **Приёмка (критерий успеха №5):** обязательная ручная проверка на **реальном iPhone** — авиарежим → добавить товар в корзину → убедиться, что корзина сохранилась и кнопка отправки заблокирована. Симулятор не годится.
