# Phase 5: Структура данных двухуровневой навигации — Context

**Gathered:** 2026-06-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Этап делает **только слой данных** двухуровневой навигации. Никакого UI.

Доставляет:
1. Карту структуры (JSON рядом с `category_map.json`): разделы → подгруппы → категории, с порядком.
2. Доработку `upload.py`: для каждого товара проставляются НОВЫЕ поля «Подгруппа» и «Раздел» в Google Sheet.
3. Перекладку групп по смыслу (на уровне категорий, не товаров): расформирование «Стоевъ и Сэнсой», разделение «Конфеты и печенье», варпаки Мистраль → «Крупы и бакалея».

**Вне этого этапа:** витрина (аккордеон разделов — Этап 6), админ-панель с выбором подгруппы (Этап 7). Существующий пайплайн загрузки и подушка безопасности НЕ трогаются.

**Согласованная структура (5 разделов → подгруппы), из PROJECT.md — НЕ переспрашивать:**
1. **Сладкое** → Шоколад и батончики · Конфеты *(Подарочные — кластером внутри)* · Печенье и вафли · Детское
2. **Напитки** → Воды и газировки · Соки · Чай и кофе · Энергетики *(последними)*
3. **Крупы, лапша, бакалея** → Крупы и бакалея *(+ варпаки Мистраль)* · Лапша и каши б/п
4. **Соусы и консервация** → Соусы/кетчуп/майонез/приправы · Консервация
5. **Снэки и прикассовое** → Чипсы/сухарики/орехи/крекеры · Жвачка/Холс/цикорий
</domain>

<decisions>
## Implementation Decisions

### Формат карты структуры
- **D-01:** Один файл `scripts/structure_map.json` рядом с `category_map.json` — вложенный: разделы → подгруппы → список категорий. Единый источник правды (а не два отдельных файла «категория→подгруппа» и «подгруппа→раздел»). Покрывает STRUCT-01 и STRUCT-02 в одном месте.
- **D-02:** Порядок везде = **позиция в списке** (массиве), без числовых полей сортировки (`order: 10, 20…`). Переставить раздел/подгруппу/категорию = подвинуть строку в JSON. Причина: владелец-непрограммист правит руками, числовые поля быстро рассинхронизируются. Покрывает STRUCT-03.
- **D-03:** Раскладка делается на уровне **категорий** (117 ключей `category_map.json`), а не товаров поштучно. Категории уже несут смысл (`«СэнСой Соусы»`, `«Стоевъ Консервация овощная»`, `«Стоевъ Сок»`) — поэтому «Стоевъ и Сэнсой» разваливается по смыслу без ручной разметки каждого товара. Покрывает REGRP-01.

### Колонка «Группа» (обратная совместимость)
- **D-04:** Старая колонка «Группа» **остаётся нетронутой** (старые 14 групп, текущая витрина продолжает по ней работать). «Подгруппа» и «Раздел» добавляются как ДВЕ НОВЫЕ независимые колонки. Приём expand-contract: на Этапе 6 витрина переключается на новые поля, на Этапе 7 решается судьба «Группы». Цель — ноль риска сломать живую витрину между этапами 5 и 6.

### Кластеризация и порядок
- **D-05:** «Подарочные кучей внутри Конфет» и «Энергетики последними в Напитках» реализуются через порядок в `structure_map.json` (D-02). `upload.py` сортирует товары по (порядок раздела, порядок подгруппы, порядок категории внутри подгруппы) — кластеры получаются автоматически, без отдельного поля. Покрывает STRUCT-05.
- **D-06:** «Подарочные» = вся текущая группа **«Коробочные конфеты»** (7 категорий). Эти категории идут подряд в конце списка категорий подгруппы «Конфеты».

### Раскладка спорных категорий (решено владельцем)
- **D-07:** `Let's Be` → подгруппа **«Воды и газировки»**.
- **D-08:** `Продако` → подгруппа **«Воды и газировки»**.
- **D-09:** `Квас` → подгруппа **«Воды и газировки»**.
- **D-10:** Разделение «Конфеты и печенье»: `Сладонеж` (= вафли) → «Печенье и вафли»; конфетные категории → «Конфеты». Покрывает REGRP-02.
- **D-11:** Варпаки Мистраль → «Крупы и бакалея» (категории `«Мистраль Крупы варпак»` и т.п. уже там — подтвердить покрытие). Покрывает REGRP-03.

### Полнота и сверка (защита Success-критерия №1)
- **D-12:** В `upload.py` — валидация покрытия: любая активная категория, не найденная в `structure_map.json`, падает в «Новинки» (или явный fallback «Прочее») с предупреждением в лог. Ничего не теряется молча — по образцу уже работающей изоляции новинок.
- **D-13:** Перед боевым прогоном — сгенерировать человекочитаемый предпросмотр «раздел → подгруппа → категории (+ счётчики товаров)» для ручной сверки владельцем. Боевое закрепление только после сверки.

### Claude's Discretion
- Полное содержимое `structure_map.json` (распределение всех 117 категорий по подгруппам) собирает планировщик/исполнитель по согласованной структуре выше; владелец сверяет результат через D-13.
- Точные имена новых полей-колонок в Sheet («Подгруппа», «Раздел») и их позиция в заголовке.
- Механизм генерации предпросмотра (отдельный скрипт vs флаг `--preview`/dry-run у `upload.py`).
</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `load_category_map()` (`upload.py:82`) — готовый паттерн чтения JSON-карты из `SCRIPT_DIR`; копируется под `load_structure_map()` с graceful-fallback при отсутствии файла.
- `apply_group_mapping()` (`upload.py:404`) — добавляет `display_group` по `category_map`; рядом добавляется проставление подгруппы/раздела.
- Логика «Новинки» — первая позиция в `GROUP_ORDER`, изоляция нераспознанного; переиспользуется как fallback при непокрытой категории (D-12).

### Established Patterns
- **Данные вне кода:** `category_map.json`, `badges.json`, `photo_overrides.json` — JSON рядом со скриптом, частичный/регистронезависимый поиск; `structure_map.json` следует тому же принципу.
- **Память правок (Этап 3):** вкладка «Правки» накладывается поверх авто-маппинга — структура не должна конфликтовать с уже применёнными правками группы (важно для Этапа 7).
- **Подушка безопасности (`sheet_tool.py`):** бэкап «Товары_BACKUP» + авто-откат при «подозрительно мало товаров» — добавление колонок не должно ломать порог/бэкап.

### Integration Points
- `upload.py main()` — после `apply_group_mapping()` добавить раскладку по `structure_map.json` + сортировку (D-05) + валидацию покрытия (D-12).
- Заголовок и строки Sheet (`upload.py:645`) — две новые колонки. Витрина (Next.js API `lib/sheets.ts`, диапазон чтения) читает их только на Этапе 6 — на Этапе 5 поля заполняются «про запас».
</code_context>
