<domain>
## Phase Boundary

Роль «Торговый» получает **дополнительный** режим вывода «Быстрый набор»: плотные строки с
миниатюрой фото, названием, ценой с подписью единицы и полем количества (прямой ввод числа
с клавиатуры + шаг «+/−»). Товар добавляется в корзину прямо из строки — без флипа карточки
и галереи. Шаг и подпись учитывают фасовку товара (счёт в родной единице: шт / блок / коробка
/ упаковка / пак / пачка / ящик / кг). Количество мгновенно отражается в корзине и итоге,
ограничено остатком (кап по `stock`). Режим скрыт в роли «Клиент» и НЕ является дефолтом.

**Закрывает требования:** QORD-01..05 (T1 — quick-order, T2 — шаг кратно упаковке).

**Чистый фронт** (только `git push` → Vercel). Сервер daniella в этом этапе НЕ трогаем.

**Вне объёма этапа 21 (важно):**
- Отображение остатка числом + фильтр «в наличии» → **этап 22** (STOCK-01..02). В строке набора
  остаток показываем скромно, как в текущем режиме «Список», без нового фильтра.
- Правка единицы фасовки в админ-панели → **этап 21b** (серверная работа, см. Deferred).
- Число «штук в упаковке» / пересчёт «блок → N шт» → не делаем (см. D-05).
</domain>

<decisions>
## Implementation Decisions

### Включение и место режима
- **D-01:** Презентация остаётся **дефолтом и главным** режимом для роли «Торговый». Ключевой
  сценарий приложения — **презентар**: торговый показывает клиенту актуальный товар, наличие,
  реальные цены и описания из прайса. Сами заявки торговый бьёт во внешней программе (AkiTorg 2.0),
  поэтому «Быстрый набор» — вторичный, вспомогательный путь и НЕ должен вытеснять Презентацию.
- **D-02:** «Быстрый набор» — **отдельный дополнительный режим вывода** (в дополнение к
  Список / Сетка / Презентация), видимый только в роли «Торговый», с быстрым возвратом в Презентацию.
  Не дефолт ни для торгового, ни (тем более) для клиента. Усиливает QORD-04.

### Вид плотной строки
- **D-03:** Строка набора = **небольшая миниатюра фото** + название + цена с подписью единицы +
  поле количества (`QuantityInput`, прямой ввод + «+/−»). Фото обязательны («торговый должен видеть,
  что листает»). Без флипа и без открытия галереи.

### Единица счёта и кратность упаковки
- **D-04:** Считаем каждый товар в его **родной единице** (гибрид): штучный — в штуках, блочный —
  в блоках, коробочный — в коробках и т.д. Единица берётся из `getPackaging(group, name)`.
  Шаг «+/−» = **±1 целая единица**; подпись единицы стоит у поля и у кнопки быстрого шага
  (например «+1 блок»). Дробные значения не вводим.
- **D-05:** **Число «штук в упаковке» НЕ вводим.** Обоснование от владельца: цена и остаток в
  прайсах уже указаны за единицу продажи (у одних — за штуку, у других — за пак/упаковку/блок),
  поэтому `price × quantity` и кап по `stock` корректны без пересчёта. Отдельное число штук в
  упаковке потребовало бы стабильного SKU (задел под v2.0) и ненадёжно при угадывании — это и есть
  риск «надёжность данных о фасовке».
- **D-06:** Фронт читает единицу товара через **новый хелпер `getUnit(product)`** — «шов» под
  будущую ручную правку. В этапе 21 `getUnit` просто возвращает `getPackaging(product.group,
  product.name)`. В этапе 21b тот же хелпер научим сначала смотреть ручную правку (переопределение),
  а `getPackaging()` останется значением по умолчанию — быстрый набор при этом повторно не трогаем.

### Корзина, остаток, производительность
- **D-07:** Переиспользуем **существующую корзину** (`useCart`/`CartProvider`, localStorage
  `catalog-cart`), `QuantityInput` и `AddToCartButton`. Количество из строки пишется в ту же
  корзину и мгновенно отражается в счётчике/итоге (QORD-03). Ввод «0» / пустое поле = удаление
  позиции (штатное поведение `QuantityInput`).
- **D-08:** Кап по остатку — переиспользуем существующий (`Math.min(quantity, stock)` в `useCart`,
  `disabled` на «+», обрезание в `QuantityInput`). Новую логику не изобретаем.
- **D-09:** Виртуализацию списка (~800 строк) **не вводим заранее** — только если на практике
  появятся заметные подвисания при наборе (QORD-05).
- **D-10 (заметка планировщику, low-prio):** единицу заказа в снимке истории/тексте заказа сейчас
  жёстко ставится `'шт'` (`cart/page.tsx`). При наличии `getUnit` разумно подставлять реальную
  единицу — но это мелочь, не блокирует этап.

### Claude's Discretion
- Точная вёрстка плотной строки, размер миниатюры, поведение клавиатуры (inputMode numeric),
  оформление подписи единицы и кнопки шага — на усмотрение исполнителя (roadmap: «UI hint: yes»,
  можно уточнить через `/gsd-ui-phase 21`).
- Механика переключения режимов (как показать новый режим в `CatalogSettings`, иконка/подпись).
</decisions>

## Existing Code Insights

### Reusable Assets
- **`QuantityInput.tsx`**: готовое поле прямого ввода с коммитом и капом по `max` — сердце строки набора.
- **`AddToCartButton.tsx`** + **`useCart`**: добавление в корзину и кап по остатку уже реализованы.
- **Режим «Список» в `ProductCard.tsx`** (строки ~368–505): готовый плотный ряд с миниатюрой 56×56 —
  ближайший аналог для строки быстрого набора.
- **`getPackaging()`**: источник подписи единицы — обернуть в `getUnit(product)`.
- **`useRole` (`ready`/`role`)**: готовый SSR-safe гейт для показа режима только роли `sales`.

### Established Patterns
- **Ветвление по роли, не по устройству**: новый UI включать по `role==='sales'` и только после
  `ready` (иначе ошибка гидратации). Паттерн уже применён в `CatalogView`/`CatalogSettings`.
- **`viewMode` в localStorage** (`list`/`grid`/`presentation`, дефолт `presentation`): добавление
  4-го режима идёт по этому же механизму.
- **Кап по `stock`** уже продублирован в нескольких местах — не плодить новую логику, переиспользовать.
- **force-dynamic** на витрине и `/api/products` НЕ трогать (иначе сломается живое управление из админки).

### Integration Points
- Новый режим «Быстрый набор» подключается в `CatalogView` + переключатель в `CatalogSettings`
  (видимость по роли `sales`).
- Хелпер `getUnit(product)` — новая тонкая обёртка над `getPackaging()`; единая точка для этапа 21b.
- Запись количества идёт в существующий `useCart` (той же корзиной пользуется отправка заказа).

<specifics>
## Specific Ideas

- Владелец: приложение = **презентар** для показа клиенту (актуальные наличие/цены/описания из прайса);
  заявки — во внешней CRM (AkiTorg 2.0). Быстрый набор — вторичный сценарий «набить себе».
- Владелец: часть карточек имеет **неверную единицу** в текущих правилах `packaging.ts` (пишет
  «упаковка» там, где «штука», и наоборот) — отсюда потребность в правке (этап 21b).
- Цены в прайсах — «по-разному»: у одних товаров за штуку, у других за пак/упаковку/блок (обоснование D-05).
</specifics>
