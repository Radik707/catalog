  <action>
    Создай клиентский модуль `lib/catalogDb.ts` с комментариями на русском. Импортируй `openDB` (и тип `IDBPDatabase`) из `idb`, `Product` из `@/lib/types`.

    Константы: `DB_NAME = "catalog-db"`, `DB_VERSION = 1`, имена stores `PRODUCTS_STORE = "products"`, `META_STORE = "meta"`. Внутри store `products` массив `Product[]` хранится под одним фиксированным ключом `PRODUCTS_KEY = "all"` (упрощённый формат по Claude's Discretion — не object-store-per-record). Store `meta` хранит произвольные пары ключ/значение.

    Функция открытия базы `getDb()`: вызывает `openDB(DB_NAME, DB_VERSION, { upgrade(db, oldVersion) { ... } })`. В upgrade-колбэке создавай оба store через `db.createObjectStore` ТОЛЬКО если их ещё нет (`if (!db.objectStoreNames.contains(...))`). Это и есть задел под версионирование схемы: при росте `DB_VERSION` upgrade-колбэк вызовется с прежним `oldVersion` и сможет мигрировать/пересоздать store, не ломая каталог. Никаких keyPath/autoIncrement — пишем по явному ключу.

    Экспортируй четыре async-функции:
    - `getProducts(): Promise<Product[]>` — `db.get(PRODUCTS_STORE, PRODUCTS_KEY)`; вернуть пустой массив `[]`, если значения нет (первый запуск).
    - `saveProducts(products: Product[]): Promise<void>` — `db.put(PRODUCTS_STORE, products, PRODUCTS_KEY)`.
    - `getMeta<T = unknown>(key: string): Promise<T | undefined>` — `db.get(META_STORE, key)`; используется для `syncTimestamp` и `prevImageUrls` (задел этапов 12–13).
    - `saveMeta(key: string, value: unknown): Promise<void>` — `db.put(META_STORE, value, key)`.

    Все обращения к IndexedDB — только через этот файл (единственная точка доступа к IDB API в проекте). Не использовать localStorage (анти-паттерн №4). Модуль исполняется в браузере — не добавляй серверного кода; обращения к `indexedDB` оборачиваются внутри функций (не на верхнем уровне модуля), чтобы импорт был безопасен.
