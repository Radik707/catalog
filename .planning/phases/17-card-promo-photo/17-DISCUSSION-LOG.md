## Сортировка и разделы (ключевой разворот)

| Вариант | Описание | Выбран |
|---------|----------|--------|
| A. Разворачивать в плоский список | Сортировка → единый список через весь каталог | |
| B. Сортировать внутри подгрупп | Разделы на месте, порядок внутри подгруппы | |
| C. Только в поиске/фильтрах | На «Каталоге» сортировки нет | |

**User's choice:** Свободный ответ — **сортировку не делать вообще.**
**Notes:** Владелец привёл сильное обоснование: (1) каталог разноплановый, сваливать всё в
кучу по цене бессмысленно — мелкие дешёвые позиции всплывут наверх, основные товары уедут
вниз; (2) человек заходит за конкретной группой, а не за «самым дешёвым», цену смотрит уже
внутри группы; (3) «по наличию» бессмысленна — заканчивающиеся товары (остаток ≤1) и так
скрываются ежедневным обновлением; (4) «по цене» некорректна даже внутри группы из-за разных
единиц фасовки (600 ₽ за пак vs 60 ₽ за штуку у похожих товаров раскидает их в разные концы).
Вывод: «оставляем разделение только на группы, не изобретаем велосипед». SORT-01..03 отклонены.

## Новая возможность: раскрытие фото клиентом (вместо сортировки)

| Вариант | Описание | Выбран |
|---------|----------|--------|
| Клиенту ♥ + кнопка раскрытия под ним | Клиент получает вторую кнопку (только при наличии фото); агент без изменений | ✓ |
| Всем ролям отдельная кнопка | Агенту дублирует стрелки — лишнее | |
| Иконка-лупа 🔍 | — | |
| Иконка-стрелки (как у агента) | «В разные стороны», единообразно и понятнее | ✓ |

**User's choice:** Клиенту сердечко + под ним **стрелки в разные стороны** (как у агента),
не лупа. Агента не трогаем.
**Notes:** Закрывает реальный пробел — сейчас клиент не может открыть фото на весь экран
(тап переворачивает карточку, стрелки только у агента). Делаем нативно и очевидно.
