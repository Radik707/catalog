### Решения

Решения зафиксированы в PROJECT.md (раздел Key Decisions).
Актуальные для текущей работы:

- Поддерживать оба формата 1С одновременно (авто-определение; уточняется у 1С-программиста в понедельник)

- Управление через админ-панель с памятью правок (не через code/scripts)
- Подушка безопасности обязательна при любых изменениях пайплайна
- [01-01] Тесты GREEN с первого запуска — существующий парсер корректен, изменений кода не потребовалось
- [01-01] «Новинки» — первая позиция в GROUP_ORDER, чтобы новые товары были заметны сразу
- [01-02] Серверные операции — только через субагента sysadmin (новое правило проекта)
- [01-02] На сервере скрипты запускать через venv /opt/apps/catalog/.venv (системный python3 без gspread)
- [01-02] Dry-run: 871 товар, новинок 16% — риск «хрупкой группировки / много ложных новинок» на практике не подтвердился
- [02-01] PROCESS_LOCK через threading.Lock; acquire(blocking=False) — единственный источник правды «идёт обработка»
- [02-01] Атомарная запись history.json через tempfile.mkstemp + os.replace — защита от повреждения при сбое
- [02-01] Поллинг /history каждые 4 с; останавливается когда нет processing-записей; кнопка «Обновить» разблокируется немедленно
- [03-01] Схема вкладки «Правки»: колонки Товар | Тип | Значение (расширяемая, D-02)
- [03-01] Фото/описание через override-поля photo_override/desc_override (вариант а, D-04)
- [03-01] Бэкап вкладки «Правки» в Этапе 3 не создаётся (upload.py только читает, T-03-05 accepted)
- [03-01] WorksheetNotFound → log.info (норма); Exception → log.warning (ошибка доступа)
- [03-02] Миграция разовая: после удаления словарей из upload.py повторный запуск migrate_overrides.py невозможен — это ожидаемо
