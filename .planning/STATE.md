## Ключевые риски v1.5

- **Хрупкий ключ матчинга (этап 19):** товары из локальной истории сопоставляются с каталогом по нормализованному имени — ключ хрупкий. Для пилота — мягкая деградация («товар больше недоступен»); надёжный SKU (O6) — задел под v2.0.
- **force-dynamic:** не добавлять ISR/кэш на витрину и `/api/products` — сломает живое управление из админ-панели (грабля этапа 8).
- **Офлайн-совместимость:** новые экраны (история заказов, история поиска, «Главная») читать офлайн-безопасно (localStorage/IndexedDB), без сетевых зависимостей при старте; standalone-PWA + safe-area снизу не ломать (как в этапе 14).
- **SSR-гидратация:** роль нельзя читать до монтирования — нейтральный дефолт, паттерн `useDeviceClass`; нижние табы и «Главная» рендерятся только после `ready`.
- **Честность истории заказов:** не называть «статус» — только «Отправленные заказы»; серверная история — задел под v2.0/Supabase.
- **Только роль «Клиент»:** все новые экраны v1.5 — для роли «Клиент»; роль «Торговый» (планшет) не задеваем.
