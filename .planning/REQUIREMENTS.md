## Требования v1.4 «Фундамент разделения аудиторий»

Объём текущей вехи. Каждое требование привязывается к этапу дорожной карты.

### Роль «Торговый / Клиент» (ROLE)

- [x] **ROLE-01**: При первом заходе на новом устройстве роль по умолчанию — «Клиент» (для всех устройств); «Агент» выбирается вручную в настройках. Автоопределения роли по типу устройства нет (решение этапа 15, см. CONTEXT.md D-02)
- [x] **ROLE-02**: Пользователь может вручную сменить роль в настройках; выбор сохраняется на устройстве и переживает перезагрузку и работу офлайн
- [x] **ROLE-03**: Поведение интерфейса (угловое действие карточки, главное действие в шапке, дефолтная плотность сетки) следует роли, а не типу устройства — «торговый с телефона» и «клиент с большого экрана» получают свой опыт после смены роли
- [x] **ROLE-04**: До загрузки страницы роль нейтральна — нет скачка вёрстки и ошибки гидратации (SSR-безопасно, как у текущего определения устройства)

### Локальная история заказов (HIST)

- [x] **HIST-01**: После отправки заказа (Telegram или MAX) заказ сохраняется в локальную историю на устройстве: позиции, количества, цены на момент заказа, сумма, дата-время, канал
- [x] **HIST-02**: История переживает закрытие вкладки/приложения и доступна офлайн (по образцу офлайн-корзины v1.3)
- [x] **HIST-03**: История честно подписана как «Отправленные заказы» — это «что я отправил», а не статус приёмки/доставки
- [x] **HIST-04**: Пользователь может очистить историю; битые/неполные записи не ломают её отображение

### Сортировка витрины (SORT)

- [ ] **SORT-01**: На витрине можно выбрать сортировку — по названию, по цене (возр./убыв.), по наличию
- [ ] **SORT-02**: Сортировка по цене учитывает выбранную форму цен (+5% Ефимова) — порядок честный для выбранной формы
- [ ] **SORT-03**: Сортировка работает вместе с поиском, фильтрами (хит/новинка/избранное) и разделами — ничего из существующего не ломается

### Мерч-стикеры (MERCH)

- [ ] **MERCH-01**: Товар с бейджем «акция»/скидкой показывает заметный стикер поверх фото (в углу), не перекрывая название и цену

## Будущие требования (необязательные улучшения)

Полезны, но не входят в MVP вехи; добавим при необходимости.

- **SORT-04**: Дефолт сортировки зависит от роли (торговый — наличие/название; клиент — цена/новизна)
- **MERCH-02**: Зачёркнутая старая цена рядом с текущей — требует поля «старая цена» в данных (сейчас его нет); включить, если заведём источник цены-до-акции
- **SEARCH-01**: История запросов и подсказки в поиске — перенесено в веху v1.5 (этап 20), здесь только фундамент
