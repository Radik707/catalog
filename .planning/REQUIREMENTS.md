# Requirements: Каталог «Вкусный Дом» — автоматизация и админ-управление

**Defined:** 2026-06-06
**Core Value:** Каталог всегда актуален и не «ломается» — вечером залили прайсы, утром витрина корректна.

## v1 Requirements

Требования текущей вехи. Каждое привязывается к этапу дорожной карты.

### Поддержка форматов прайсов (FMT)

- [ ] **FMT-01**: `upload.py` авто-определяет формат файла (старый/новый) и парсит соответствующим образом
- [ ] **FMT-02**: новый формат разбирается верно — название из колонки D, цена из N, остаток из O; строки-дубли (название в A) пропускаются
- [ ] **FMT-03**: старый формат прайсов продолжает работать без изменений (оба формата поддерживаются)
- [ ] **FMT-04**: при невозможности прочитать текущие группы (нужны для нового формата) обновление прерывается с понятной ошибкой, а не сваливает все товары в «Новинки»
- [ ] **FMT-05**: новый формат проверен боевым прогоном на реальных файлах (≈871 товар парсится, каталог обновляется корректно)

### Группировка и новинки (GRP)

- [ ] **GRP-01**: для нового формата группа товара берётся из текущего каталога по нормализованному названию
- [ ] **GRP-02**: товары, которых не было в каталоге, попадают в группу «Новинки» и получают бейдж «новинка»
- [ ] **GRP-03**: «Новинки» корректно показываются в витрине (как группа и во вкладке «Новинка»)

### Страница загрузчика (UPL)

- [ ] **UPL-01**: после отправки оператор сразу видит «файлы отправлены» — без показа результата обработки и без ожидания
- [ ] **UPL-02**: обработка идёт асинхронно на сервере (оператор не блокируется)
- [ ] **UPL-03**: результат (успех / ошибка / подозрение «мало товаров») приходит только владельцу в Telegram
- [ ] **UPL-04**: на странице показывается короткая история загрузок (дата/время, число товаров или ошибка)

### Админ-панель владельца (ADM)

- [ ] **ADM-01**: владелец открывает защищённую админ-панель (отдельный секретный доступ)
- [ ] **ADM-02**: владелец может вручную назначить/изменить категорию (группу) товара
- [ ] **ADM-03**: владелец может точечно исправить неверно распознанные поля товара
- [ ] **ADM-04**: владелец может привязать фото к новому товару прямо из панели (без запуска агента)
- [ ] **ADM-05**: панель выделяет товары, требующие внимания (новинки, без группы, без фото)

### Память правок (MEM)

- [ ] **MEM-01**: ручные правки владельца (группа, привязка фото, исправления) сохраняются персистентно (не в коде, переживают перезапись листа «Товары»)
- [ ] **MEM-02**: при следующих обновлениях сохранённые правки применяются автоматически
- [ ] **MEM-03**: ручная работа требуется только для реально новых товаров — повторно размечать уже размеченное не нужно

## v2 Requirements

Отложено на будущее.

### Автоновинки (NEW)

- **NEW-01**: бейдж «новинка» автоматически снимается через 2 недели, товар остаётся в каталоге
- **NEW-02**: дата появления товара хранится и используется для срока новизны

## Out of Scope

| Feature | Reason |
|---------|--------|
| Автоновинки (2 недели) | Отдельная будущая веха, зависит от памяти правок |
| Перенос сайта с Vercel | Хостинг сайта не меняем |
| Массовая загрузка фото для всех товаров | В этой вехе только точечная привязка фото новым |
| Приём файлов через мессенджер (MAX/VK/Telegram) | Отклонено — файлы грузятся через веб-страницу |
