### Phase 8: Скрытие товаров «глазиком»

**Цель:** Владелец одним нажатием скрывает ненужный товар с витрины (и так же возвращает) — без правки кода и таблиц; скрытие переживает перепрогон прайсов.

**Зависит от:** Этапа 7 (память правок и типы правок — уже реализованы)

**Требования:** HIDE-01, HIDE-02, HIDE-03, HIDE-04, HIDE-05

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. Владелец нажимает глазик в карточке админ-панели — товар исчезает с витрины; повторный клик возвращает товар обратно.
2. Скрытая карточка в панели визуально тускнеет, иконка меняется — сразу видно, что товар скрыт.
3. После перепрогона прайсов (`upload.py`) скрытые товары по-прежнему остаются скрытыми.
4. Запрос `/api/products` не возвращает скрытые товары — браузер клиента их не получает вообще.
5. Товар остаётся в листе «Товары» Google Sheet (не удаляется) — владелец может вернуть его в любой момент.

**Планы:** 4 plans

- [x] 08-02-PLAN.md — Витрина: Product.hidden, диапазон A2:L, фильтр скрытых на сервере (HIDE-05) ✅ 2026-06-11
- [x] 08-03-PLAN.md — Админ-панель: /save type=`скрыт`, кнопка-глазик, optimistic toggle, тусклая карточка + чип, фильтр видимости (HIDE-01..03) ✅ 2026-06-11
- [x] 08-04-PLAN.md — Раздельный деплой (Vercel + сисадмин) + сквозная проверка цикла скрыть/вернуть (HIDE-01..05) ✅ 2026-06-11

**Заметки по реализации** (из бэклога, проработан 2026-06-10):

### Phase 9: Десктопный вид витрины

**Цель:** Витрина каталога удобна и читаема на большом экране — карточки, сетка и навигация используют доступное пространство, не выглядят «растянутыми».

**Зависит от:** Этапа 6 (двухуровневая навигация витрины — уже реализована)

**Требования:** DESK-01, DESK-02, DESK-03, DESK-04

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. На широком экране (≥1280px) витрина показывает больше колонок или просторнее расставляет карточки — пространство не пустует.
2. Карточка товара на десктопе выглядит пропорционально: фото не слишком маленькое, название читается без обрезания, цена и кнопка корзины не «разъезжаются».
3. Двухуровневая навигация (разделы → подгруппы) на десктопе удобна для клика мышью — зоны нажатия достаточные, нет мелких нечитаемых элементов.
4. На мобильном экране (≤768px) вид не ухудшается по сравнению с текущим состоянием.

### Phase 10: Фундамент SW и Manifest

**Цель:** Service worker подключён и работает корректно; каталог отвечает критериям PWA — устанавливается как приложение с иконкой и запускается без адресной строки браузера.

**Зависит от:** Ничего (первый этап вехи v1.3)

**Требования:** PWA-01

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. В DevTools → Application → Service Workers статус SW — `activated and running`; при перезагрузке страницы SW не падает с ошибкой.
2. Заголовок ответа для `/sw.js` содержит `Cache-Control: max-age=0, must-revalidate` — Vercel не кэширует SW с `immutable`.
3. Каталог открывается в standalone-режиме (без адресной строки браузера) после установки через браузерное меню.
4. В dev-режиме (`npm run dev`) SW отключён — разработка не ломается из-за кэша; PWA-поведение проверяется только через `npm run build && npm start`.
5. `public/sw.js` и `public/swe-worker*.js` добавлены в `.gitignore` — сгенерированные файлы не попадают в репозиторий.

### Phase 11: Слой данных (IndexedDB + useCatalogSync)

**Цель:** Товары, цены, остатки и структура навигации хранятся в IndexedDB на устройстве агента и переживают закрытие вкладки; при офлайн-запуске каталог показывает данные из локального хранилища.

**Зависит от:** Этапа 10 (SW активен — без него офлайн-стратегия не работает)

**Требования:** OFF-01, OFF-02, OFF-03

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. После однократной загрузки каталога агент переводит телефон в авиарежим — каталог открывается и показывает весь список товаров с ценами, остатками и бейджами.
2. В авиарежиме работает навигация по разделам и подгруппам, поиск и фильтры — по данным, загруженным ранее.
3. В DevTools → Application → IndexedDB видна база `catalog-db` со stores `products` и `meta`; данные присутствуют после закрытия и повторного открытия вкладки.
4. После первой синхронизации `navigator.storage.persist()` вызван — браузер уведомлён, что данные не должны вытесняться (особенно важно на iOS с 7-дневным eviction).
5. Проверка на реальном iPhone: авиарежим → открыть каталог → товары видны (тест обязателен, эмулятор недостаточен).

### Phase 12: Офлайн-UX (индикаторы и корзина)

**Цель:** Агент всегда понимает, онлайн он или офлайн и насколько свежи данные; корзина работает без сети, но попытка отправить заказ офлайн не теряет данные молча.

**Зависит от:** Этапа 11 (данные в IndexedDB — есть что показывать и с чем работать)

**Требования:** SYNC-03, CART-01, CART-02

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. В шапке каталога отображается полоска «Офлайн • Данные за 08:30» — агент видит режим и время последней синхронизации; при подключении к сети полоска исчезает или меняет цвет.
2. Если данные старше 24 часов, индикатор окрашивается в жёлтый — агент понимает, что каталог может быть устаревшим.
3. В авиарежиме товары добавляются в корзину и удаляются из неё — корзина работает полностью офлайн.
4. Кнопка «Отправить заказ» в авиарежиме заблокирована и содержит понятное пояснение («Нужен интернет для отправки»); заказ в корзине при этом сохраняется и не теряется.
5. Проверка на реальном iPhone: авиарежим → добавить товар в корзину → убедиться, что корзина сохранилась и кнопка отправки заблокирована.

### Phase 13: Синхронизация фото

**Цель:** Фото просмотренных товаров доступны офлайн; ежедневное обновление докачивает только новые фото, не перекачивая весь набор (~900 штук); кэш фото не переполняет хранилище телефона.

**Зависит от:** Этапа 11 (IndexedDB с `meta.prevImageUrls` для diff; данные каталога — источник URL фото для сравнения)

**Требования:** IMG-01, IMG-02, IMG-03, SYNC-01, SYNC-02

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. Фото товара, открытого ранее при наличии сети, отображается в авиарежиме — в том числе в полноэкранном просмотрщике с зумом.
2. Нажатие кнопки «Обновить» при наличии сети подтягивает свежий каталог; в Cache Storage появляются только URL новых фото — старые не перекачиваются заново.
3. В DevTools → Application → Cache Storage → Cloudinary-кэш не превышает `maxEntries: 450` записей — лимит соблюдается автоматически (CacheFirst + ExpirationPlugin).
4. На iPhone кэш фото не вызывает ошибку `QuotaExceededError` и не блокирует загрузку каталога; суммарный объём кэша остаётся в пределах ~50 МБ.
5. Проверка на реальном iPhone: просмотреть 5–10 товаров → авиарежим → открыть те же карточки → фото видны без сети.

### Phase 14: Install Prompt (Android + iOS)

**Цель:** Агент узнаёт о возможности установить каталог как приложение и умеет это сделать на своём телефоне — на Android получает баннер, на iPhone — понятную пошаговую инструкцию.

**Зависит от:** Этапа 10 (manifest + SW активны — без них промпт не появится), Этапа 11 (офлайн-каталог работает — логично предлагать установку когда продукт уже полезен)

**Требования:** PWA-02

**Критерии успеха** (что должно быть ПРАВДОЙ по завершении):

1. На Android-устройстве после просмотра каталога появляется баннер «Установить приложение»; после установки каталог открывается с домашнего экрана без браузерной строки.
2. На iPhone в Safari появляется bottom-sheet с пошаговой инструкцией «Нажмите "Поделиться" → "На экран Домой"»; инструкция понятна без технических знаний.
3. Промпт показывается однократно — повторные визиты не надоедают агенту баннером при каждом открытии.
4. В standalone-режиме (после установки) каталог отображается корректно: нет лишних отступов, нет адресной строки, интерфейс занимает весь экран.
5. Проверка на реальном iPhone: Safari → открыть каталог → увидеть bottom-sheet → следовать инструкции → каталог установлен на домашний экран → открывается без браузера.
