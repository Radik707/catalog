# Дорожная карта: Каталог «Вкусный Дом» — автоматизация и админ-управление

## Обзор

Веха переводит каталог с ручного обслуживания программистом на самостоятельное управление владельцем.
Путь: сначала починить текущую блокировку (новый формат 1С не задеплоен, каталог на старых данных),
затем дать оператору прозрачную страницу загрузки, выстроить слой памяти правок и наконец
открыть владельцу полноценную админ-панель.
После вехи ежедневное обновление каталога не требует участия программиста.

## Этапы

- [ ] **Этап 1: Боевой прогон нового формата 1С** — довести поддержку нового формата до реального прогона на сервере
- [x] **Этап 2: Переделка страницы загрузчика** — асинхронная обработка, история загрузок, результат в Telegram
- [ ] **Этап 3: Память правок** — персистентный слой правок владельца, авто-применение при обновлениях
- [ ] **Этап 4: Админ-панель владельца** — защищённая панель: категории, фото, точечные исправления

## Детали этапов

### Phase 1: Боевой прогон нового формата 1С

**Goal**: Новый формат прайсов 1С корректно парсится, деплоится на сервер daniella и прогоняется на реальных файлах — каталог обновляется актуальными данными
**Mode:** mvp
**Depends on**: Ничего (первый этап, срочный)
**Requirements**: FMT-01, FMT-02, FMT-03, FMT-04, FMT-05, GRP-01, GRP-02, GRP-03
**Success Criteria** (что должно быть ПРАВДОЙ):

  1. Оператор загружает файл нового формата — каталог обновляется ~871 товаром без ручного вмешательства
  2. Файл старого формата по-прежнему обрабатывается корректно (оба формата работают одновременно)
  3. Товары, которых раньше не было в каталоге, появляются в группе «Новинки» с бейджем «новинка» и видны во вкладке «Новинка»
  4. Если текущие группы недоступны (сбой чтения из Sheet), обновление прерывается с понятным сообщением об ошибке — не сваливает всё в «Новинки»
  5. Dry-run на реальных файлах из `/opt/apps/catalog/uploader/last_batch/` выдаёт корректный счёт товаров до деплоя

### Phase 2: Переделка страницы загрузчика

**Goal**: Оператор видит мгновенный отклик «файлы отправлены», обработка идёт в фоне, результат приходит только владельцу в Telegram; страница показывает историю загрузок
**Mode:** mvp
**Depends on**: Этап 1
**Requirements**: UPL-01, UPL-02, UPL-03, UPL-04
**Success Criteria** (что должно быть ПРАВДОЙ):

  1. После нажатия «Загрузить» оператор немедленно видит подтверждение «файлы отправлены» — страница не зависает в ожидании
  2. Владелец получает Telegram-сообщение с итогом (число товаров или описание ошибки) после завершения обработки — оператор этого не видит
  3. На странице загрузчика отображается таблица последних загрузок: дата/время, результат (N товаров или ошибка)
  4. При ошибке обработки оператор не видит деталей — только нейтральное «отправлено», Telegram-уведомление идёт владельцу

### Phase 3: Память правок

**Goal**: Ручные правки владельца (категория, фото, исправления полей) сохраняются персистентно и применяются автоматически при каждом следующем обновлении каталога
**Mode:** mvp
**Depends on**: Этап 1
**Requirements**: MEM-01, MEM-02, MEM-03
**Success Criteria** (что должно быть ПРАВДОЙ):

  1. Правка, внесённая владельцем (категория, фото), сохраняется в файле на сервере и не теряется при перезапуске сервиса или перезаписи листа «Товары»
  2. При следующем запуске `upload.py` сохранённые правки применяются автоматически — владелец не повторяет ручную работу
  3. Новые товары (которых ещё нет в памяти правок) требуют ручной разметки; уже размеченные — нет

### Phase 4: Админ-панель владельца

**Goal**: Владелец самостоятельно назначает категории, исправляет поля, привязывает фото к новым товарам через защищённую веб-панель — без участия программиста
**Mode:** mvp
**Depends on**: Этап 3
**Requirements**: ADM-01, ADM-02, ADM-03, ADM-04, ADM-05
**Success Criteria** (что должно быть ПРАВДОЙ):

  1. Владелец открывает панель по секретной ссылке (отдельной от ссылки загрузчика) и видит список товаров, требующих внимания
  2. Владелец может изменить категорию (группу) любого товара через форму в панели — изменение применяется при следующем обновлении каталога
  3. Владелец может привязать фото к товару прямо из панели (без запуска агента или скрипта)
  4. Панель явно выделяет товары без группы, без фото и с бейджем «новинка» — их легко найти в списке
  5. Точечное исправление поля товара (название, цена — если ошиблась 1С) сохраняется и применяется автоматически
