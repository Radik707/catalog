## 🚀 Крупные фичи (кандидаты в новые вехи)

- **Telegram-бот «Каталог-консультант»** — бот консультирует клиентов по товарам (ИИ) и принимает заказы на тех же данных. Спроектирован в CLAUDE.md (grammY + Gemini, корзина в Vercel KV). _L · 📋 готов к планированию_
- **Автоновинки** — новые товары из прайсов автоматически получают бейдж «новинка» на 2 недели, потом он снимается сам. _M · 💡_
- **Интеграция с AkiTorg** — заявка с каталога уходит в приложение торгового агента (через 1С; публичного API нет — нужно исследование). _L · 💡 нужно исследование_
- **Офлайн-режим (мини-приложение / PWA)** — каталог работает как приложение: фото и данные кэшируются при утренней загрузке и доступны без интернета. Без сети можно листать, переключать вкладки, открывать фото на увеличение, набирать корзину. Технически — PWA + service worker + стратегия кэша (≈900 фото — нужен умный кэш, не всё сразу). _L · 💡 нужна отдельная проработка_
- **Многопользовательский режим (SaaS-платформа) — кандидат в веху v2.0** — превратить персональный каталог в продукт для других торгпредов: у каждого свой вход (логин/пароль), свой профиль, своя админ-панель, свои товары/фото/ссылка-каталог, свой Telegram для заказов. _XL · 💡 нужна отдельная проработка (обсуждено 2026-06-11)_

  **Проработка (senior-оценка 2026-06-11):**
  - **Суть:** смена архитектуры с single-tenant (один хозяин) на multi-tenant (много арендаторов). Это отдельный ПРОДУКТ, не доработка каталога. Объём — недели-месяцы.
  - **Две новые большие подсистемы:** (1) аутентификация — аккаунты, хэш паролей, сессии, сброс; (2) изоляция данных (multi-tenancy) — каждый видит/правит только своё.
  - **Стек:** Google Sheets как БД НЕ тянет multi-tenant (лимиты API + риск утечки между арендаторами). Правильный путь — переезд на настоящую БД со встроенным входом (рекомендация: **Supabase** = Postgres + Auth + row-level security из коробки). Витрина остаётся Next.js на Vercel, адрес у каждого свой (`catalog/[tenant]` или поддомен). Фото — папка Cloudinary на тенанта.
  - **Главные риски/подводные камни:** (а) безопасность критична — утечка ЧУЖИХ данных бьёт по репутации; (б) **парсер чужих прайсов** — у каждого торгпреда свой непредсказуемый формат Excel из 1С; масштабировать парсер на чужие форматы, возможно, труднее самого входа и БД; (в) «обвязка продукта» — регистрация, биллинг/подписка, поддержка, юр. сторона хранения чужих данных.
  - **Рекомендация сеньора:** не строить полный SaaS сразу. Сначала проверить СПРОС (есть ли реальные торгпреды, готовые пользоваться/платить — 1–2 живых интересанта важнее кода). Технически — поэтапно: «мульти-аккаунт лайт» пилот на 2–3 пользователях → потом честный переезд на Supabase.
  - **Открытые вопросы (решить при старте вехи):** монетизация (продаём подписку или для себя?), стратегия парсера чужих прайсов, модель цен (у каждого свои?), брендинг каталога под торгпреда.
  - **Тайминг:** НЕ сейчас. Текущая веха v1.2 (этап 10 — десктоп-админка) в работе. Это будущая веха v2.0, отдельный заход — оформляется через `/gsd:new-milestone`.

## 🔧 Техдолг и безопасность

- **[CR-01] Новый формат 1С не получает раздел/подгруппу** — у товаров нового формата 1С пустая категория (`source_category=""`), поэтому `apply_structure_mapping` сваливает их все в «Прочее». Сейчас латентно (боевые файлы — старого формата, с категориями). Корень не вылечен: сегодняшние 4 «Без категории» заткнуты точечно. Фикс требует (а) уточнения формата у 1С-программиста, (б) продуктового решения о подгруппе по умолчанию для группы «Конфеты и печенье» (она маппится в 2 подгруппы). Нужен тест с `source_category==""`. _M · ⏸ техдолг, перенесён из вехи v1.1 (см. `.planning/todos/deferred/cr-01-*`)_
- **Ротация токена Telegram-бота** — токен был засвечен в чате, рекомендована замена. _S · 💡_
- **Логи перепрогона в загрузчике** — сейчас подробный вывод upload.py теряется; писать «хвост» в журнал службы для диагностики правок. _S · 💡 (заметил сисадмин)_
- **Чистка пустого листа «Товары_NEW»** — артефакт-болванка остаётся после прогонов без отката. _S · 💡 (заметил сисадмин)_
- **[WR-04] Дубль имени `TelegramButton`** — локальная кнопка заказа в `cart/page.tsx` и плавающая кнопка-помощник `components/TelegramButton.tsx` названы одинаково; легко поправить «не тот» компонент. Переименовать кнопку заказа в `SendOrderButton`. _S · 💡 (code-review этапа 12)_
