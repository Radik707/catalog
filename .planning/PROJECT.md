# Каталог «Вкусный Дом» — автоматизация и админ-управление

## What This Is

B2B-каталог товаров «Вкусный Дом»: мобильный сайт (Next.js на Vercel), который читает товары из Google-таблицы и показывает их оптовым клиентам — торговый представитель демонстрирует каталог, клиент набирает корзину и отправляет заказ. Данные обновляются из Excel-прайсов поставщиков. Текущая веха — автоматизировать ежедневное обновление каталога и дать владельцу удобное самостоятельное управление категориями и фото, без участия программиста.

## Core Value

Каталог всегда актуален и не «ломается»: вечером оператор залил свежие прайсы — к утру каталог обновлён и корректен, без ручной возни и без риска показать клиентам битую витрину.

## Context

- **Доработка существующего проекта (brownfield).** Полная карта кода — в `.planning/codebase/` (ARCHITECTURE, STACK, STRUCTURE, CONVENTIONS, TESTING, INTEGRATIONS, CONCERNS).
- **Поток данных:** Excel-прайсы → веб-загрузчик (`uploader/app.py`) → `scripts/upload.py` → Google Sheet «Товары» → Next.js API → витрина. Telegram-бот (`admin_bot/`) — боковой канал уведомлений/решений.
- **Сервер daniella** (`/opt/apps/catalog`, `ssh my-vps`): службы `catalog-uploader` и `catalog-admin-bot` (systemd), nginx+TLS, Telegram через SOCKS-прокси `127.0.0.1:1080` (РФ-ограничения). Сайт — на Vercel.
- **Толчок вехи:** поставщик сменил формат выгрузки 1С (нет колонок-категорий) — текущий парсер выдал 0 товаров; подушка безопасности отработала (откат). Нужно поддержать новый формат и дать владельцу инструмент управления категориями/фото.
- **Известные риски** (подробно — `.planning/codebase/CONCERNS.md`): `upload.py` перезаписывает весь лист «Товары»; группировка нового формата по названию — хрупкая; нет автотестов; Telegram-прокси — единая точка отказа; токен бота был засвечен в чате (рекомендована ротация).

## Constraints

- **Tech stack**: сайт — Next.js на Vercel (хостинг не менять); серверная обработка — Python (Flask) + systemd + nginx на daniella — так уже выстроено, не переусложнять.
- **Данные**: Google Sheets как «база»; `upload.py` перезаписывает лист «Товары» целиком — обязательна подушка безопасности (бэкап/откат) при любых изменениях пайплайна.
- **Security**: секреты не в git (`credentials.json`, `.env`); доступ к серверу только через `ssh my-vps`; правки владельца и секреты не должны утекать.
- **Формат прайсов**: к понедельнику уточняется у 1С-программиста, возможен возврат старого формата — поддерживать оба формата одновременно.
- **Пользователи**: владелец (Олег, вайбкодер — не программист) и оператор поставщика (грузит файлы) — интерфейсы должны быть простыми и «защищёнными от ошибки».

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Приём файлов через веб-страницу, а не мессенджер-бот | Файлы приходят оператору в MAX; MAX-бот требует ИП/ООО, VK неудобен, Telegram нестабилен в РФ — веб-страница проще и без лишних пересылок | ✓ Good |
| Поддержать оба формата 1С с авто-определением | Формат может вернуться к старому (уточняется у 1С) — не ломать рабочий путь | — Pending |
| Новые товары нового формата → «Новинки» + бейдж | Категорий в новом формате нет; изолировать новое для ручной разборки владельцем | — Pending |
| Управление категориями/фото через админ-панель с памятью правок | Владелец-непрограммист должен править сам; правки не должны теряться при обновлениях | — Pending |
| Подушка безопасности обязательна для пайплайна | `upload.py` перезаписывает весь каталог — нельзя оставлять витрину битой | ✓ Good |
